Before you start

A README file is a short, plain-text document that sits alongside a dataset and explains what it is, who made it, how it was collected, and how it is organized — so that you, or anyone else, can understand and reuse it correctly later on.

This generator walks you through four short sections. As you type, a live preview builds your README in the standard plain-text format on the right (or below, on small screens). When you're done, the Output step lets you copy the finished file or download it.

1. General Information

Title, overview, authors, contributors, dates, location, funding, and ethics approval.

2. Sharing / Access Information

Licences, restrictions, related publications, related datasets, and how the dataset should be cited.

3. Data & File Overview

A file list or folder tree, relationships between files, and version notes.

4. Output

Review, copy, or download your finished README.txt file.

General Information

All fields save automatically to the preview as you type. Required fields are marked *.

1.1 Title *

1.2 Overview *

A brief description (2-3 sentences max) to guide the reader through the available materials, from start to finish. Include the purpose, nature, and scope of the dataset.

1.3 Authors *

It's best practice to have at least two contacts. This supports dataset longevity if researchers move to a different institution or retire.

1.4 Contributors

List the names and contributions of everyone involved with collection, collaboration, processing, analysis, and/or submission.

1.5 Date of Collection

Provide a single date, a range, or an approximate date. Suggested format YYYY-MM-DD.

1.6 Geographic Information

If relevant to your dataset, provide the location of data collection - latitude/longitude, or city/region, province, country. Example: Ottawa, ON

1.7 Funding Information

Include the granting agency and number for funding or sponsorship sources that supported the collection of the data. Example: Support for this research was provided by the Natural Sciences and Engineering Research Council (NSERC) of Canada via a Discovery Grant (RGPIN-2023-04821) to A.J. Turk.

1.8 Ethics Information

If relevant to your dataset, include details on the research ethics board(s) which granted approval to the project. Example: This research was approved by the Carleton University Research Ethics Board for Psychology (CUREB-B 108675).

Sharing / Access Information

All fields save automatically to the preview as you type. Required fields are marked *.

2.1 Certification *

This statement is included in your README to confirm the dataset is ready to share.

2.2 Licence / Restrictions

Note any licence placed on the data (e.g., a Creative Commons licence), or any restrictions on its use, redistribution, or reproduction. Example: This dataset is made available under a CC BY 4.0 licence.

2.3 Links to Publications

Links or citations to any publications that cite or use this dataset.

2.4 Links to Other Locations

Links to other publicly accessible locations where this dataset (or parts of it) can be found, such as a data repository DOI. Example: Available via the Carleton University Institutional Data Repository, at https://doi.org/XXXXXX/XXXX

2.5 Related / Ancillary Datasets

Was this data derived from, or related to, another source or dataset? If so, list it/them here.

2.6 Terms of Use

Any additional terms of use, embargo periods, or conditions readers should be aware of before reusing this data.

2.7 Recommended Citation *

How should someone cite this dataset? Example: Lastname, Firstname (2026). "Dataset Title" [Data set]. https://doi.org/XXXXXX/XXXX, Borealis, V#

Data & File Overview

All fields save automatically to the preview as you type. Required fields are marked *.

3.1 File List *

List every file (and folder) in the dataset with a one-line description of each, or paste in a plain-text folder tree. The Folder Structure Generator Tool can generate a text folder-tree diagram for you to paste here.

3.2 Relationships Between Files

Describe how files relate to one another, if that isn't obvious from the file list. Example: 2025-06-01_codebook.csv explains the variables in 2025-06-01_survey-clean.csv.

3.3 Additional Related Data Not Included

Mention any data that was collected as part of this project but is not included in this data package, and briefly explain why.

3.4 Versions

Is this the first version of the dataset being shared? Note: this section normally isn't needed for a first version - keep it in mind for future updates.

Information on Team List

    
NISO's Contributor Roles Taxonomy (CRediT) provides a list of roles typically played by contributors to scholarly output. See credit.niso.org.

  





  

    
ORCID

    
ORCID (Open Researcher and Contributor ID) is a persistent identifier for authors and contributors that connects your research outputs, including datasets, to an automatically updated record unique to you. Register at orcid.org/register.

  





  

    
ROR

    
The Research Organization Registry (ROR) is a persistent identifier for research institutions. Carleton University's ROR is https://ror.org/02qtvee93.

  





  

    
Email

    
Consider including your institutional email as well as an alternate contact you can be reached at if you relocate to a different institution.
